## 2. Wording

### 2.1 RQ2.1 ¶1 GUI (`results.tex:159`) — ✏️ (matches checklist A1)
- CloudAnalyst / CloudReports: last commits 2016-08 / 2017-09 (GitHub
  `vondrt4/CloudAnalyst-interactive`, `thiagotts/CloudReports`); current CloudSim is
  7.0.1 (2025-08, `Cloudslab/cloudsim` releases). Not viable GUIs for current CloudSim.
- OpenDC GUI still exists (`opendc-web/` in `atlarge-research/opendc`).

### 2.2 RQ2.1 ¶2 energy output (`results.tex:161`) — ✏️ (checklist A2)
- **CloudSim/NCS:** CSV holds *cumulative datacenter energy (J)*, per-host values
  only in the log (`container/core/PowerContainerDatacenter.java:240–273`). Interval is a
  `double` in seconds, lower bound `minTimeBetweenEvents` = 0.01 s, configurable
  (`core/CloudSim.java:63,154–161`) → **not** max 1 Hz. Framework logs per-host
  utilization/energy by default (`Log.java:32`) → not "largely user-defined".
- **OpenDC:** `host.parquet` has `power_draw` (W) **and** `energy_usage` (J since last
  sample; `SimPsu` accumulates `power × ms × 0.001`, `HostTableReaderImpl.getEnergyUsage`
  = delta). 1 s minimum holds (`exportInterval` → `Duration.ofSeconds`, `ScenarioRunnerKt`).
- **SimGrid:** after `sg_host_energy_plugin_init()` the plugin prints per-host and total
  energy (J) at simulation end (`src/plugins/host_energy.cpp`,
  `on_host_destruction`/`on_simulation_end`); only the time series needs user code
  (`simple.cpp:97–127`).

### 2.3 Documentation ¶ (`results.tex:164`) — ✏️ (checklist B1/B2)
- OpenDC footnote URL `https://atlarge-research.github.io/opendc/docs/intro` → **404**;
  now `https://opendc.org/learn/intro` (OpenDC2 + OpenDC3 docs).
- "CloudSim distribution docs generally up to date" — bundled
  `simulators/cloudsim/documentation/src/main/resources/readme.txt` still says Java 8 + Ant

### 2.4 RQ2.2 ¶1 topology (`results.tex:153`) — ✏️ (checklist C1, C2)
- "DISSECT-CF offers the most parameters" — not supported by corrected table
  (NCS 8, CloudSim 7, DISSECT-CF 7 distinct of 9). Supported alternative: DISSECT-CF
  makes the most of them **mandatory and per host** (`PhysicalMachine.java:782–783`
  throws without a power-state set; each PM needs its own `Repository`).
- DISSECT-CF also requires policies (`IaaSService(Scheduler, PhysicalMachineController)`,
  `iaas/IaaSService.java:180`), fewer than CloudSim.
- SimGrid/OpenDC are simplest because they model fewer *layers* (SimGrid: no VM/
  allocation layer, no memory; OpenDC: no network/storage) — **not** fewer features
  overall (SimGrid has the broadest energy support, `tab:energyFuncs`).
- IPC: SimGrid uses FLOPS, not an IPC variant (XML reference `<host speed>` in flop/s).
  "More accurate in principle" only applies to absolute (instruction/flop) workloads;
  here workloads are relative, so CPU speed cancels (`TraceExperiment.java:260`,
  `SingleJobRunner.java:119–120`, `simple.cpp:75`).

### 2.5 RQ2.2 ¶2 workloads (`results.tex:155`) — ✏️ (checklist C3, C4)
- OpenDC "cannot be defined in code" → "not via the experiment runner" (loader hardcodes
  format `"opendc-vm"`, `ComputeWorkloadLoader.load()`; code API exists, see 1.2).
  `opendc-trace-api.jar` also bundles SWF/GWF/Bitbrains/Azure/WTF/WfFormat readers,
  not wired into the simulation pipeline.
- SimGrid trace loading is not fully DIY: replay framework
  `xbt_replay_action_register()` / `simgrid::xbt::replay_runner` (Examples, "Traces
  Replay as a Workload"); DAX/DOT loaders are DAG-only (`create_DAG_from_DAX`/`_dot`).
- SimGrid "memory consumption" → disk I/O; "computation duration" → amount of flops.
- "DISSECT-CF is a discrete simulator" → CloudSim is also discrete-event
  (`core/SimEvent.java:23`, `double time`); the difference is DISSECT-CF's integer,
  user-defined tick (`Timed.java:65` `long fireCounter`, class doc).

### 2.6 Experiment execution, IPC (`experimentExecution.tex:66`) — ✏️ (not in checklist)
- "The mean of these 30 IPC values was then taken to be used to configure the cloud
  simulators" — only CloudSim/NCS use it (`TraceExperiment.java:126`). DISSECT-CF reads
  but ignores it (`SWFExperiment.java:93,142`); SimGrid uses a fixed GFLOPS value
  (`trace-generation/gen_traces.py:106`). Suggested sentence: `plan/R1.4_cpu_speed_ipc.md` §1.
- Train Ticket IPC is bimodal (runs 1–12 ≈ 1.05, 13–30 ≈ 0.77; mean 0.88 fits neither,
  `trace-generation/ipc_trainticket.data`) — supports "context-dependent".
