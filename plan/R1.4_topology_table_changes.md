## 2. CloudSim (and NetworkCloudSim, which inherits all of this)

Base path: `simulators/cloudsim/modules/cloudsim/src/main/java/org/cloudbus/cloudsim/`

### Memory: bytes → MB
- The Javadoc gives no unit; the codebase convention is MB.
- `simulators/cloudsim/modules/cloudsim-examples/src/main/java/org/cloudbus/cloudsim/examples/CloudSimExample1.java:177`
  `int ram = 2048; // host memory (MB)` (also `:99` `// vm memory (MB)`).
- The study itself uses MB:
  `.../examples/TraceExperiment.java:127` `int ram = ((Number) host.get("ram_gb")).intValue() * (int) 1e3; // in MB`.

### Host network bandwidth: B/s → bit/s
- `core/HostEntity.java:256` — `Gets the host bw (in bits/s).`
- (Study: `TraceExperiment.java:129` sets `bandwidth_gbps * 1e9`, i.e. bit/s,
  though its comment says "in bytes".)

### Storage size / network bandwidth / disk bandwidth: ✗ → MB / ✓ / MB/s (note a)
- `HarddriveStorage.java:48` `/** The total capacity of the hard drive in MB. */`
- `HarddriveStorage.java:51` `/** The maximum transfer rate in MB/sec. */`
- `HarddriveStorage.java:54` `/** The latency of the hard drive in seconds. */`
- `HarddriveStorage.java:64` `@param capacity the capacity in MByte`
- `SanStorage.java:35–40` `SanStorage(double capacity, double bandwidth, double networkLatency)`
  — `@param bandwidth Network bandwidth` (**no unit documented** → cell shows ✓ only).
- Hosts also take a mandatory storage capacity:
  `power/PowerHost.java:57–64` `PowerHost(int id, RamProvisioner, BwProvisioner, long storage, …)`.
- These devices are passed to the datacenter as a `storageList` (datacenter level,
  hence note a). The study passed an empty list:
  `TraceExperiment.java:358` `LinkedList<Storage> storageList = new LinkedList<>(); // we are not adding SAN devices by now`.

### Network link latency: ✗ → seconds
- `NetworkTopology.java:124` `public static void addLink(int srcId, int destId, double bw, double lat)`
  (also loadable from a BRITE file, `NetworkTopology.java:80` `buildNetworkTopology`).
- The latency is applied to messages: `NetworkTopology.java:103` builds `delayMatrix`,
  used at `NetworkTopology.java:248` `double delay = delayMatrix.getDelay(...)`.
- Unit: simulation time units, which CloudSim treats as seconds (cf.
  `HarddriveStorage.java:54`, and the power module's W·sec energy accounting).

### Network link bandwidth: stays ✗, adds note b
- `NetworkTopology.java:106` builds `bwMatrix = createBwMatrix(graph, false);`
- `bwMatrix` is declared at `:58` and assigned at `:106`, and **never read anywhere
  in the codebase** (grep over `modules/cloudsim/src/main/java`), so bandwidth is
  accepted but has no effect → ✗ with explanatory note.

## 5. OpenDC

### Memory: bytes → MiB
- In the OpenDC version used (`simulators/openDC/OpenDCExperimentRunner/lib/`, jars
  dated 2025-03-22), `memorySize` is a unit-typed `DataSize`; a plain number is read as
  **MiB**. Bytecode of `org.opendc.compute.topology.TopologyFactories`
  (`opendc-compute-topology.jar`): `MemoryJSONSpec.getMemorySize` →
  `DataSize.toMiB` → `MemoryUnit(…, long size)`.
- **Empirical check** — loading the study's own topology through OpenDC's loader
  (`TopologyFactories.clusterTopology(File)`) logs:
  `UnitSerializer - deserialization of number with no unit of measure for unit 'DataSize', assuming it is in MiB.`
  and stores `memory size = 403726925824` (MiB). A control file with
  `"memorySize": "376 GiB"` stores `385024` (MiB).
- Current docs agree: https://opendc.org/learn/documentation/Units — "A plain
  number … is read in the default unit of its quantity" (data size: MiB).
- **Side effect in the study:** `simulators/openDC/gen_base_topology.py:17` writes
  `ram_gb * 1073741824  # in bits` (actually bytes), which OpenDC reads as MiB →
  the simulated host had ≈ 376 PiB of memory. Energy results are unaffected
  (OpenDC's power model is CPU-utilization only), but the table unit is MiB.

### CPU speed: MHz — verified, unchanged
- Same bytecode: `CPUJSONSpec.getCoreSpeed` → `Frequency.toMHz`. The probe logs
  `assuming it is in MHz` and stores `2100.0` for the study's `"coreSpeed": 2100`.

### No network or storage: verified
- `HostJSONSpec` fields are only `name, cpu, memory, powerModel, count`;
  `ClusterJSONSpec` adds `powerSource, battery, location` (javap of
  `opendc-compute-topology.jar`). No network/storage parameters → ✗ cells stand.

## 6. SimGrid

The SimGrid library is not vendored in this repo (only
`simulators/simgrid/simgrid-template-s4u-master/`), so evidence is the upstream
platform reference: https://simgrid.org/doc/latest/XML_reference.html

### Storage / Disk bandwidth: ✗ → B/s, bit/s (note c)
- `<disk>` tag with attributes `id`, `read_bw`, `write_bw` (unit required; no size
  attribute → Storage/Size stays ✗).

### Network link bandwidth: bps → B/s, bit/s (note c); latency: ms → s, ms, … (note c)
- `<link bandwidth=…>` requires an explicit unit (bytes or bits, powers of 2 or 10,
  e.g. `Bps`, `Mbps`); `latency` accepts `ps, ns, us, ms, s, …`.
- The old cells "bps" / "ms" were just the units the study happened to write:
  `traces/platform.xml:18` `<link id='1' bandwidth='1000000000.0bps' latency='0.25ms'>`.

### Memory ✗, host network ✗: verified
- `<host>` has `speed` (flop/s per core) and `core`; no memory attribute.
